# Short native recovery probe v1

Ticket [22](https://github.com/loldlm1/.codex/issues/22) selects one bounded
disposable TypeScript fixture, two manual compactions and one exact-thread
process restart. It is common preparation, separately reported as `probe` usage;
it is outside both per-arm adoption gates. Neither measured application task is
implemented or provided to the fixture workers.

The fixture has one public function: finite numbers are truncated and clamped to
0..9; nonfinite numbers return zero. A fresh implementation worker uses the actual
installed ECC `tdd-workflow`, explicitly replacing Matt's delegated TDD. It runs
the meaningful intended RED and the same GREEN target before ordinary local
commit/integration. The actual Matt coordinator and installed execution/recovery
contracts preserve one concise committed record. Separate fresh Standards and Spec
reviewers inspect the integrated result, within the unchanged native concurrency
cap. No extra orchestration or RED/GREEN checkpoint commits are selected.

To avoid another install, the fixture explicitly borrowed the already pinned
preflight npm dependency tree. Final inspection found shared Vite/Vitest result,
duration and transformed-module cache directories inside that tree. All 16 current
fixture tests actually ran, including the intended RED; no measured feature or
outcome exists. This probe makes no cold-toolchain or cache-performance claim.
The measured arms require fresh arm-owned dependencies and these default caches,
with no preflight/other-arm tree reuse.

Workers use `fork_turns: none`, inherited gpt-6.1-sol and explicit `xhigh`; root
retains accepted `ultra/default/cap2`. The implementation has its own worktree and
dedicated exact-worktree Graphify server. Read-only reviewers use the integrated
root and its corresponding server. Verify actual spawn arguments, model contexts,
command working directories, MCP calls/source answers and completed workers.

The private client uses the supported native 0.167.0 app-server APIs
`thread/start`, `turn/start`, `thread/compact/start`, `thread/items/list`,
`thread/read` and `thread/resume`. It does not enable internal raw events,
diagnostic request tracing, decryption or a different automatic-compaction
threshold. Account and hook status are checked through native APIs; the exact
previously reviewed authenticated home is used in place. Owned process overrides
keep ECC/CLV2, RTK databases and npm/temp/XDG/graph state separate. No account,
trust, session or cache state is transferred into another runtime home; private
canonical ledger snapshots are retained only as accounting evidence. The browser
keeps its accepted pinned
npx launch vector and a newly provisioned dependency tree whose full file closure
matches the accepted transport.

For each boundary, require all of:

- A successful supported request and matching context-compaction item start/end,
  with no observed failure/error in that operation.
- A newly persisted canonical `compacted` checkpoint with nonempty replacement
  history, actual distinct response/window identity and a checkpoint/source digest.
- A unique actual response-usage ledger record owned by that thread/session;
  reconcile ordinary/ledger differences with the persisted compaction usage.
- All bounded workers complete before proceeding; the same record recovers scope,
  immutable baseline, completed work/checks, authorization, tool/graph policy and
  one retained next action after both boundaries.

An acknowledgement or completion message alone is insufficient. After the second
installed checkpoint, close the process, preserve full canonical source snapshots,
start a different PID and call `thread/resume` with the exact original thread ID.
Do not provide replacement history or a different rollout path. Verify unchanged
committed head/record at resume before the recovery turn.

The resumed coordinator reads/reconciles the record, executes actual RTK tests and
actual root Graphify MCP source queries. It appends a harmless exported sentinel,
observes the guard's actual `STALE_GRAPH` MCP error before rebuilding, rebuilds
fresh through the approved code-only helper and obtains the sentinel's actual
source answer. It removes the sentinel, verifies the original behavior, commits
the same record, rebuilds again after the last source/commit change and checks the
final actual source answer. Registration, self-reported intent or preflight graph
reuse does not establish this behavior.

Finally close the native tree. Feed complete original root/descendant canonical
sources, supported notifications and exact pre-restart snapshots into the unchanged
[strict collector](usage-v1.md). Preserve actual lineage, sessions, turns, original
timestamps, response identities, source hashes, both checkpoint identities and
replays. Identical replays add zero; a malformed or unexplained record keeps
evidence incomplete. Report all six counters, root/descendant/compaction subsets,
actual peak input and the separate common-probe total. Root coordination owns the
long-lived preparation tree and final complete-window acceptance separately.

This short manual probe cannot establish automatic near-limit behavior, quality
at a greater-than-100k context, absence of unobservable upstream requests or
universal billing completeness. No filler, additional probe or measured run is
used to fill a missing accounting claim. The four-run
[measurement contract](measurement-v1.md), starter pins, quality rubric, isolation,
first-use allocation and counterbalanced order remain fixed before outcomes.

[sanitized proof](recovery-proof-v1.json) records original source/checkpoint hashes,
actual model/spawn evidence, all six counters and the separate tool observations.

unchanged committed head and record before its recovery turn. Scope, both immutable
baselines, completed work/reviews, authorization limits, tool policy and next action
were retained. The same record was updated through final fixture commit `5809124`.
